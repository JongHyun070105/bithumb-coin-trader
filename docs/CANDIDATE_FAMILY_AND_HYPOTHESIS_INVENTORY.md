# Candidate Family and Hypothesis Inventory

This is a provenance inventory, not a promotion or a claim that historical
metrics are valid. Every strategy family remains unselected and must be
retested through the governed research path before candidate governance can
advance it. The machine-readable inventory is generated by
`research candidate-families export`; that command refuses to overwrite a
different existing snapshot.

Seed the append-only hypothesis ledger with:

```bash
python -m bithumb_coin_trader.research_infra.cli hypotheses catalog-seed
python -m bithumb_coin_trader.research_infra.cli hypotheses catalog-list
```

The ledger is hash chained. Repeating the seed command is idempotent; changing
an existing hypothesis requires a new hypothesis ID. `H1`–`H5` retain the
existing microstructure/cross-exchange hypotheses. Additional records map the
strategy research, including absolute momentum, mean reversion, breakouts,
regime allocation, cross-asset momentum, pullbacks, Core+Satellite, session
volume, shock/rebound and meta-selection, to their source documents and code.

## Historical record handling

- The prior V4 finalist and the reported Core+Satellite `+48.43%` result are
  historical references only. The supporting Core+Satellite report is absent
  from this branch; the registry says so explicitly.
- V7.1 remains marked invalidated. V8.1 remains marked failed under the
  leave-one-asset-out analysis. Opportunity research records that its old
  holdout was already used and must not be reopened.
- The inventory does not reinterpret, delete, or rewrite any of those reports.
- The exact AOA/expert-origin hypothesis records are not present in this
  checkout. The catalog therefore contains one `UNKNOWN` placeholder with
  `role = HYPOTHESIS_GENERATION_ONLY`; it has no executable features and cannot
  be promoted.

## Current batch adapter boundary

The inventory covers the discovered internal strategy source modules and
historical families. The generic resumable `research-batch` currently has
governed adapters only for its cash, buy-and-hold, randomized-placebo controls
and the SMA runner fixture. It rejects other inventoried family/strategy
combinations instead of silently running a different implementation under a
familiar strategy name. Building and validating adapters for those families
remains SAFE_NOW work; the inventory alone does not satisfy candidate-family
execution integration.

No record in this catalog changes:

```text
ALPHA = UNPROVEN
PAPER = NOT_STARTED
LIVE = DISABLED
PRIVATE_API = DISABLED
```
